# Cerber Anonim Photo

Сайт для анонимной загрузки фото и выдачи приватной ссылки на каждую фотографию.

## Приватность

- В ссылке используется отдельный 256-битный ключ после `#`. Эта часть URL не отправляется в HTTP-запросе и не попадает в обычные журналы сервера.
- Сервер хранит только SHA-256 хеш ключа, а не сам ключ.
- После проверки ключа браузер получает короткую `HttpOnly`, `SameSite=Strict` сессию. Прямой `/image/<id>` без неё возвращает `404`.
- Изображения отдаются с `Cache-Control: private, no-store` и не могут встраиваться с другого сайта.
- Старые публичные ссылки автоматически отзываются. Сами файлы сохраняются, а новые ключи восстановления записываются в закрытый файл `.legacy-photo-keys.json` внутри `UPLOAD_DIR`.

Приватную ссылку следует передавать только тому, кому разрешён просмотр. Любой получивший полную ссылку с `#key=...` сможет открыть фотографию.

Полная ссылка остаётся в адресной строке после просмотра: её можно скопировать и передать другому человеку. Ключ ссылки не истекает. При повторном открытии браузер получает новую временную сессию, отдельно для каждой фотографии. Автоматического удаления фотографий по времени в приложении нет. Постоянное хранение требует Persistent Disk или настроенного R2 без правил автоматического удаления объектов.

```bash
npm start
```


## Render

Для постоянного хранения фото на Render подключён Persistent Disk:

```text
UPLOAD_DIR=/var/data/uploads
```

Диск сохраняет фото при перезапусках и деплоях, но не является резервной копией: при удалении сервиса или диска данные могут быть потеряны.

## Резервная копия в Cloudflare R2

Сервер умеет автоматически делать вторую копию каждой фотографии в приватный bucket Cloudflare R2. Вместе с файлом сохраняется запись с ID и хешем ключа доступа. Если Render-диск окажется пустым, фотография и её запись восстановятся из R2 при открытии прежней ссылки.

Создай приватный R2 bucket и токен с правами `Object Read & Write` только для этого bucket. Затем добавь в Render:

```text
R2_BUCKET=cerber-photo-backup
R2_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
R2_ACCESS_KEY_ID=<Access Key ID>
R2_SECRET_ACCESS_KEY=<Secret Access Key>
R2_PREFIX=cerber-photo
R2_RETRY_MS=60000
```

Все четыре обязательные переменные `R2_*` должны быть заполнены. После перезапуска сервер проверит старые фотографии на Render-диске и скопирует отсутствующие в R2. Bucket нельзя делать публичным.

Если R2 временно недоступен, основная загрузка продолжает работать через Persistent Disk. Резервные копии ставятся в очередь и повторяются в фоне. Состояние основного хранилища и очереди резервирования доступно по `/api/health` и `/health`.

Для полного восстановления на новом Render-сервисе нужно подключить пустой Persistent Disk, задать те же переменные R2 и сохранить прежний домен. Старые приватные ссылки продолжат работать, потому что ID и хеш ключа восстанавливаются вместе с фотографиями.

Рекомендуемые настройки Render:

```text
Build Command: npm install
Start Command: npm start
Environment: Node
UPLOAD_DIR: /var/data/uploads
PHOTO_SESSION_SECRET: случайная строка длиной не меньше 32 символов
```

Если `PHOTO_SESSION_SECRET` не задан, сервер создаёт его сам в закрытом файле внутри `UPLOAD_DIR`. Для нескольких экземпляров сервиса необходимо задать одинаковое значение через секретную переменную окружения.

Дополнительные ограничения:

```text
MAX_UPLOAD_BYTES=26214400
MAX_FILE_BYTES=10485760
MAX_FILES_PER_UPLOAD=20
MAX_STORAGE_BYTES=2147483648
UPLOAD_RATE_LIMIT=10
UPLOAD_RATE_WINDOW_MS=600000
ACCESS_RATE_LIMIT=30
ACCESS_RATE_WINDOW_MS=60000
PHOTO_SESSION_TTL_SECONDS=3600
```
